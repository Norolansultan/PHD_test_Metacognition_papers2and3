# Scenario and probe file formats

One YAML file per scenario, no code. A supervisor must be able to read it without programming, and
it must be publishable as an appendix.

## Scenario file

```yaml
id: fin-def-03
version: 3
seed: 88421
duration_s: 2700
domain: land

terrain:
  file: terrain/valley_a.png     # fictional terrain
  cell_m: 100
  legend: {0: open, 1: forest, 2: water, 3: road, 4: urban}

entities:
  - {id: blue_1pl,     side: blue, kind: infantry_platoon, pos: [4200, 3100], strength: 1.0}
  - {id: blue_drone_a, side: blue, kind: drone,            pos: [4000, 3000], endurance_s: 1800}
  - {id: red_coy_x,    side: red,  kind: mech_company,     pos: [7800, 5200], strength: 0.9}

# Who observes what, and how accurately. Observations fall out of these.
sensors:
  - {entity: blue_drone_a, range_m: 3000, pos_error_m:  50, interval_s:  60}
  - {entity: blue_1pl,     range_m:  800, pos_error_m: 200, interval_s: 300}

events:
  - t: 600
    type: radio_message
    from: adjacent_bn
    text: "Enemy detachment observed at grid 78-52, moving west."
    creates_observation:
      subject: red_coy_x
      pos: [7800, 5200]
      pos_error: 400
      confidence: 0.7

  - t: 1200
    type: radio_message
    from: higher_hq
    text: "Forces withdraw. Move to area KELO."
    tag: vague_order                 # paper B starts here
    identical_all_conditions: true
    required_by_order: rules/kelo_withdrawal.yaml   # drift measure, see below

probes:
  - {t:  900, ref: p_fin03_01}
  - {t: 1500, ref: p_fin03_02, open_l3: true}

# Error injection — two types, never in the same trial
injections:
  - {after_t: 1200, type: projection_error, param: red_speed, factor: 0.6}
  # OR
  # - {after_t: 1200, type: guidance_distortion, direction: north, magnitude: medium}

fallback:
  guidance_at_s: 1500      # if no order_interpretation query has arrived by then,
                           # the interpretation arrives by radio, distortion included
```

**Sensors replace hand-authored corpora.** Observations are generated by what a sensor could see, at
the accuracy and interval declared. This removes a whole class of inconsistency between what a sensor
could have observed and what a hand-written entry claims it observed, and it makes information
scarcity structural: a region no sensor covers stays empty by construction.

## Probe file

Probes live in their own directory so one probe can serve several scenarios.

```yaml
id: p_fin03_01
level: 3
type: multiple_choice
prompt: "Where do you estimate the enemy detachment will be in 30 minutes?"
options: [A, B, C, D]
correct: C
confidence_scale: 4
```

**The answer key is an assertion, not a source.** The validator runs the scenario headless and
re-derives the answer; a mismatch fails the build. This catches both a wrong key and a model change
that silently invalidated a key — neither of which a hand-written key or a computed answer catches
alone. See [reconciliation X-03](../architecture/reconciliation.md).

## Drift rules

`required_by_order` points at a declarative rule file that computes, from world state, what the order
required in this situation. It is the reference for Paper B's dependent variable.

Where a rule cannot be written for a decision point, that point yields no drift data. The validator
reports which points those are, so the gap is known while content is being written rather than
during analysis.

## Validator rules

The validator runs on every build. A failure stops the build.

| # | Rule | What it prevents |
|---|---|---|
| V-01 | Every `probes[].ref` resolves to a probe file | Dangling references |
| V-02 | Every probe's `correct` matches the answer re-derived from a headless run | A key drifting from the model |
| V-03 | Probe accuracy in pilot data falls in 65-85 % | Sensitivity being incomputable |
| V-04 | 15-25 probes per participant; spacing 2-6 min; none in the last 60 s of a decision window; none within 30 s of a projection answer | Load-curve gaps, reactivity, contaminated ratings |
| V-05 | No probe or freeze is preceded by any cue, icon, or countdown | The measure becoming rehearsal |
| V-06 | `projection_error` and `guidance_distortion` never share a trial | Confounding reliability with integrity |
| V-07 | Injection proportions approximately 55 / 20 / 20 / 0 across the scenario | Proportion drift |
| V-08 | Distortion direction systematic within a scenario, balanced across scenarios | The manipulation being visible in its structure |
| V-09 | At least one forced branch point before guidance arrives | Self-selected exposure |
| V-10 | A radio fallback is defined for every pulled guidance | An exposure gap |
| V-11 | `required_by_order` exists for every drift-measuring point, or the point is marked as non-drift | Unmeasurable drift |
| V-12 | Study II: projections about the rear ground return at most N results before point 10 | The empty sector being quietly filled |
| V-13 | Condition-specific content does not leak: condition 1 cannot reach peer content by any route | Manipulation leakage |
| V-14 | Every log field referenced by the state-space document exists in the schema | Proxies becoming uncomputable after the fact |
| V-15 | The debrief text covers every distortion type used in the scenario | An incomplete debrief |
| V-16 | Only vocabulary defined in the glossary is used for conditions | Stale terminology |
| V-17 | Scenario duration equals the sum of its parts; freezes do not consume scenario time | Arithmetic drift |

**V-14 is the least intuitive and the most important.** The state-space document's third column
names the log fields each online proxy needs. Those fields cannot be added retroactively to data
already collected, so the validator checks that every proxy promised in Paper D is loggable.

## Content workload

| Content | Study I | Study II | Note |
|---|---|---|---|
| Scenario events and radio messages | ~100 | ~100 | Plus recording if audio is used |
| Vague order and drift rules | 1 + n rules | — | See [Study I](../studies/study-i-army.md) |
| Peer decision timeline | — | 7 sectors × ~10 decisions | Observations, not a separate system |
| Closed probes | 40-60 bank | 40-60 | Piloted to the accuracy band |
| Open Level-3 probes | 2-3 | 2-3 | Plus a coding frame |
| **Calibration battery** | **200 items** | **200 items** | Per domain, per study |
| Injection specifications | per scenario × 3 magnitudes | pending decision | Calibrated in the pilot |
| Debrief text | 1 | 1 | Covers every distortion type used |

The sensor model removed roughly 60 hand-written corpus entries and 180 distractors from the earlier
plan. What replaced them — piloting probe banks to an accuracy band — is more work than it looks,
because the band has to be found by iteration.

**The longest lead time is still expert availability.** Parameter validation, terrain realism, and
the vagueness check on the order all need the same people. Book them together.
